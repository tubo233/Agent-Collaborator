## 可重复的自动检查

使用 Node.js 24：

```sh
npm ci
npm run check
```

`check` 依次执行 ESLint、TypeScript 类型检查、测试和生产构建。测试应使用独立临时目录与端口，不依赖用户的真实任务板。

CI 配置为 `ubuntu-latest` 与 `windows-latest`，两者使用 Node 24 并执行同一组 npm 命令。实际运行状态应以目标提交对应的 [GitHub Actions](https://github.com/tubo233/Agent-Collaborator/actions) 为准；本地 Linux 成功不能替代 Windows 成功。

## 协作核心应覆盖的回归场景

- 两个调用者争抢一个 ready 任务，最多一个领取成功
- 旧版本写操作被拒绝，失败后没有半写入记录
- 未完成依赖、跨项目依赖、自引用与环不能进入有效任务图
- 有效 token 可续租；伪造 token、旧 attempt 和过期租约均被拒绝
- 租约到期后任务仍 running；人工回收后可以重新领取，旧 token 不可提交
- 交接至少有一个证据引用，提交只进入 review
- Agent actor 不能通过正常人工验收命令把任务设为 done
- 人接受 / 退回交接后，状态、attempt、handoff 与事件一致
- 空库恢复验证完整关系并废弃运行中的旧所有权；非空库拒绝恢复
- 导出不包含系统生成的 token / token hash；自由文本仍可能包含用户自行写入的敏感信息
- 重启 daemon 保留项目与历史

## HTTP / 适配器应覆盖的场景

- 本地健康检查、快照、任务详情与命令错误返回
- 非 loopback Host、外站 Origin、错误 Content-Type 和超大输入被拒绝
- 第二个 daemon 不能无声占用同一目录
- CLI 的 JSON / `@file` 输入、错误退出码、导出不覆盖、空库恢复确认
- MCP initialize、tools/list、tools/call、失败返回，且 stdout 无诊断污染
- UI、CLI 和 MCP 看到的是同一服务的状态
