# Agent 工作约定

适用于手动打开的 Codex、Claude Code、其他 MCP 客户端或使用 CLI / HTTP 的脚本。任务板不启动这些进程，不继承它们的文件权限，也不替人验收。

## 1. 选任务前

1. 读取快照或指定任务详情
2. 检查项目、目标、验收标准、依赖和已有交接
3. 只领取 `ready` 且所有依赖均为 `done` 的任务
4. 确认实际工作目录、文件修改范围和用户授权；仓库 URL / 路径引用不是操作授权

任务板没有文件锁。即使两个 Agent 分别持有不同任务，也可能同时修改同一文件。人应拆清职责，或自行安排独立 checkout / worktree 与集成步骤。

## 2. 领取后再工作

成功 claim 返回 `task`、`attempt` 和本次 `token`。保留：

- `task.id`：任务
- `attempt.id`：本次执行，不等于外部会话 ID
- `token`：本次有效执行的所有权凭据
- `task.version`：后续写入的预期版本

抢占失败不是临时网络错误；先读取最新状态，不能持续重试同一个旧版本。严禁冒充 `human` 调用人工命令来取得所有权。

token 仅保存于当前执行上下文。不要写进评论、交接、代码仓库、截图或公开日志。快照和备份不应成为找回 token 的方式；丢失 token 时由人回收后重新领取。

## 3. 工作时续租

默认租约 300 秒；通常每 60 秒主动发送一次 heartbeat。可配置单次租约在 30–3600 秒间，不能靠设置无限租约避免失联管理。

在长工具调用或离开会话之前考虑剩余时间。daemon / MCP 不会代替 Agent 自动心跳。

遇到以下情况，停止继续提交本次工作，并向人说明：

- token 已失效或租约已经过期
- 任务被回收、取消、阻塞或已进入其他状态
- expectedVersion 不匹配
- 连接失败且无法确认当前所有权

先刷新详情再判断可否重试。不要在 HTTP 超时后假设写入失败，特别是创建、领取和提交操作；响应丢失时先检查是否已经生效，避免重复记录。

## 4. 提交可验收的交接

完成实际工作后提交 handoff，使任务进入 `review`。交接至少应说明：

- **完成了什么**：对应任务目标与验收标准
- **如何验证**：真正执行的测试、输出或截图引用
- **证据在哪里**：提交哈希、文件路径或可访问 URL，并标明用途
- **还剩什么**：未完成项、已知风险、未执行的测试与下一步

证据 URI 是文本引用。任务板不会读取文件、确认链接存在，也不会判断测试陈述是否真实。`npm test 通过` 必须来自实际运行，不能用“已写测试”替代。

示例摘要：

```text
已实现任务筛选与空状态，修改 web/TaskList.tsx。
已运行：npm run typecheck，npm test，均通过。
未验证：Windows 原生浏览器与真实 Claude Code 会话。
建议人工检查：任务删除前后的筛选选项与窄屏布局。
```

不要提交密码、密钥、token、未经授权的私人文件内容。提交 handoff 后当前执行不再续租，也不要绕开验收把任务设为 `done`。

## 5. 阻塞与失联

如果需要外部决定、缺权限或前置条件无法满足，记录明确的阻塞原因；不要声称完成。人可解除阻塞或调整范围后重新安排。

如果 Agent 崩溃、关闭、长时间无心跳，租约过期后任务仍保留 `running`，以便人看到未结束的执行。人先确认它不再修改实际文件，再回收为 `ready`。新的执行会有新的 attempt/token，旧执行不能迟到覆盖结果。

## 6. 人工验收

人应检查交接、实际产物和验收标准：

- 接受：`review → done`，依赖该任务的工作才满足开工条件
- 退回：写出具体原因，任务回到 `ready`，保留旧执行与交接历史

这是本地协作流程，不是安全隔离：API 中的 actor 可由本地调用者声明。对不可信 Agent 或多用户部署，不应使用当前版本。

具体请求示例见 [CLI / REST API](api.md)，接入入口见 [MCP](mcp.md)。

## 网页领取与 Agent 领取

网页中的领取属于人工登记：凭证仅保存在当前浏览器标签页，在该页续租和提交交接。它不会自动传给 Codex、Claude Code 或其他外部会话。若希望 Agent 自己心跳与提交，请让那个 Agent 直接通过 MCP / CLI 领取，不要先在网页替它领取。外部 Agent 领取后，网页用于查看进度、评论和人工验收。
